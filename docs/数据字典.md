# 数据字典

## 1. 数据范围与通用约定

数据库为SQLite，默认文件是 `data/derived/medical_ops.db`，可由 `MEDICAL_DB_PATH` 更改。运行时建表权威定义位于 `backend/app/core/database.py`；`sql/` 下是五层参考DDL。

- 日期字段以TEXT保存 `YYYY-MM-DD`；时间戳为UTC ISO 8601文本。
- 金额和天数使用REAL，展示格式不改变存储值。
- `source_batch` 关联导入批次；ADS预刷记录的 `batch_id` 当前写为 `SYSTEM`。
- `patient_key` 为 `SHA256(salt + ":" + patient_id)` 的前24个十六进制字符，盐来自 `MEDICAL_HASH_SALT`。这是去标识化散列，不是匿名化保证。
- DWD不保存姓名、证件号、手机号等直接标识；ODS `payload_json` 保存完整原始行，仍可能含这些字段。
- DWD不声明维度外键，先落地再通过质量规则发现未映射数据。主键、唯一约束与索引见本文第8节。

## 2. 源文件字典

## 3. ODS与批次表

### `etl_batch`

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| `batch_id` | TEXT PK | 批次UUID；质量检查也会生成批次 |
| `source_table` | TEXT NOT NULL | 源标识，或 `quality` |
| `source_file` | TEXT NOT NULL | 文件名或质量规则集名称 |
| `source_sha256` | TEXT NOT NULL | 原始文件SHA-256；质量批次使用 `-` |
| `status` | TEXT NOT NULL | `RUNNING/SUCCESS/PARTIAL/FAILED` |
| `row_count` | INTEGER，默认0 | 接受行数或质量检查总行数 |
| `error_count` | INTEGER，默认0 | 错误行数或质量失败行数 |
| `started_at` / `finished_at` | TEXT | UTC开始/结束时间，结束时间可空 |
| `message` | TEXT | 最多保存部分错误详情或失败信息 |

### `ods_record`

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| `source_table` | TEXT，联合PK | 六类源标识 |
| `source_pk` | TEXT，联合PK | 源业务主键 |
| `batch_id` | TEXT NOT NULL | 最近写入批次 |
| `payload_json` | TEXT NOT NULL | 完整原始行JSON，含未进入DWD的字段 |
| `content_hash` | TEXT NOT NULL | 规范化JSON文本的SHA-256 |
| `created_at` | TEXT NOT NULL | 最近一次写入时间，不是源业务创建时间 |

联合主键为 `(source_table, source_pk)`。`INSERT OR REPLACE` 使重复导入保持幂等，同时会更新最近批次和原文。

## 4. DWD明细表

六张表均有 `source_batch TEXT NOT NULL`，表示最近导入批次，以下不再重复列出。

### `dwd_outpatient_visit`

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| `visit_id` | TEXT PK | 门诊就诊标识 |
| `patient_key` | TEXT NOT NULL | 患者散列标识 |
| `dept_code` | TEXT NOT NULL | 就诊科室编码 |
| `visit_date` | TEXT NOT NULL | 就诊日期 |
| `visit_type` | TEXT | 普通、急诊等源类型 |
| `fee_amount` | REAL，默认0 | 门诊源表费用；不用于K17/K19核心收入 |

### `dwd_inpatient_stay`

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| `visit_id` | TEXT PK | 住院就诊标识 |
| `patient_key` | TEXT NOT NULL | 患者散列标识 |
| `dept_code` | TEXT NOT NULL | 住院科室编码 |
| `bed_no` | TEXT | 源床号，不作为开放床位配置 |
| `admit_date` / `discharge_date` | TEXT | 入院/出院日期；DDL允许出院日期为空，但当前模板规范化要求有效日期 |
| `stay_days` | REAL，默认0 | 源住院日，用于K13、K29等 |

| `drug_fee` / `consumable_fee` | REAL，默认0 | 住院源表费用分项，当前核心药品/耗材指标不使用 |

### `dwd_charge_detail`

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| `charge_id` | TEXT PK | 收费明细标识 |
| `visit_id` | TEXT | 关联就诊标识，可有跨表关联失败风险 |

| `visit_type` | TEXT | 门诊、住院等，决定K17/K18归类 |

| `fee_date` | TEXT NOT NULL | 收费统计日期 |

| `amount` | REAL，默认0 | 收费金额；当前导入拒绝负数 |

### `dwd_emr_record`

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| `record_id` | TEXT PK | 病历记录标识 |
| `patient_key` / `visit_id` / `dept_code` | TEXT | 患者、就诊、科室关联 |
| `visit_date` | TEXT | 就诊日期 |
| `diagnosis` | TEXT | 诊断及源文本；不向页面提供患者病历明细查询 |
| `disease_code` | TEXT | 源病种编码；当前病种汇总使用住院表而非本表 |

### `dwd_lis_report`

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| `report_id` | TEXT PK | 检验报告标识 |
| `patient_key` / `visit_id` | TEXT | 患者与就诊关联 |
| `item_name` | TEXT | 检验项目 |
| `result_text` | TEXT | 源结果文本；仅“异常/阳性”进入异常占比分子 |
| `report_date` | TEXT | 报告日期；没有发布时间，故K36不可算 |

### `dwd_finance_day`

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| `record_id` | TEXT PK | 财务记录标识 |
| `stat_date` | TEXT NOT NULL，联合唯一 | 财务统计日期 |
| `dept_code` | TEXT NOT NULL，联合唯一 | 科室编码 |
| `revenue` / `drug_revenue` / `consumable_revenue` | REAL，默认0 | 财务日汇总；当前只入仓和质量检查，不进入K16—K25 |

唯一约束为 `(stat_date, dept_code)`。ETL的替换以 `record_id` 为主键；同日期科室不同 `record_id` 会触发唯一约束冲突，不会自动合并。

### `dwd_encounter_wide`

统一就诊明细宽表，联合主键 `(source_type, encounter_id)`。当前10,500行，覆盖门诊9,000次和住院1,500次。

| 字段组 | 含义 |
|---|---|
| `source_type` / `encounter_id` / `patient_key` | 就诊来源、业务ID、散列患者标识 |
| `dept_code` / `start_date` / `end_date` | 科室与就诊起止日期 |
| `visit_type` / `disease_code` / `diagnosis` | 就诊类型、病种和诊断摘要 |
| `outpatient_fee` / `inpatient_total_fee` / `drug_fee` / `consumable_fee` | 源就诊表费用字段；K16—K18采用门诊`fee_amount`+住院`total_fee`的账单口径，K21/K23采用收费明细的费别口径 |
| `charge_amount` / `charge_items` | 按 `visit_id` 汇总的收费金额和条目数 |
| `lis_reports` / `abnormal_lis_reports` | 关联LIS报告总数和异常/阳性数 |
| `source_batch` | 来源批次 |

该表是DWD统一明细基础，不替代六张按源拆分的标准表；当前指标主要仍从标准表和DWS计算。ODS原文和散列患者标识仍按敏感数据管理。

## 6. DWS汇总表

### `dws_dept_day`

联合主键 `(stat_date, dept_code)`，表示一个已生成的科室日。所有指标默认0。

| 字段 | 类型 | 汇总含义 |
|---|---|---|
| `stat_date` / `dept_code` | TEXT | 统计日期与科室 |
| `outpatient_visits` | INTEGER | 门诊记录数 |
| `outpatient_patients` | INTEGER | 当日该科患者散列标识去重数 |
| `outpatient_revenue` | REAL | 收费表中门诊类型金额 |
| `admissions` / `discharges` | INTEGER | 按入院日/出院日计数 |
| `inpatient_revenue` | REAL | 收费表中住院类型金额 |
| `drug_revenue` | REAL | XY、ZC收费合计 |
| `consumable_revenue` | REAL | CL收费合计 |
| `total_revenue` | REAL | 全部收费类型金额合计 |
| `stay_days` | REAL | 当日出院病例源 `stay_days` 合计 |
| `occupied_bed_days` | REAL | 住院日期展开得到的占用床日 |
| `open_bed_days` | REAL | 当日写入教学 `bed_count` |
| `lis_reports` | INTEGER | 可关联到该科就诊的报告数 |
| `abnormal_lis_reports` | INTEGER | 其中结果为“异常”或“阳性”的数量 |

### `dws_disease`

联合主键 `(disease_code, dept_code)`。字段：

- `discharges INTEGER`：该病种科室出院记录数。
- `total_fee REAL`：住院表 `total_fee` 合计，不是收费表K18。
- `stay_days REAL`：住院表源 `stay_days` 合计。

只纳入 `discharge_date IS NOT NULL AND disease_code IS NOT NULL` 的住院记录；空字符串编码未被该条件排除，但关联维度时不会匹配正式病种。

## 7. ADS与指标定义

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| `metric_code` | TEXT，联合PK | 指标编码 |
| `stat_date` | TEXT，联合PK | 日粒度写日期；周/月粒度写桶起始日 |
| `grain` | TEXT，联合PK | `day`、`week` 或 `month` |

## 8. 应用与治理表

这些表由运行应用自动创建，不属于五层业务事实表，因此未强行归入DWD/DWS/ADS参考DDL。

### `app_user`

`username TEXT PK`、`display_name TEXT NOT NULL`、`password_hash TEXT NOT NULL`、`role TEXT NOT NULL`、`dept_codes_json TEXT NOT NULL DEFAULT '[]'`、`enabled INTEGER DEFAULT 1`。

角色为 `admin/analyst/department`；空科室数组表示全院范围。密码散列使用随机盐和PBKDF2-HMAC-SHA256，不能由该字段直接还原口令。

### `audit_log`

`id INTEGER PK AUTOINCREMENT`、`trace_id TEXT NOT NULL`、`username TEXT NOT NULL`、`action TEXT NOT NULL`、`resource TEXT NOT NULL`、`detail TEXT`、`created_at TEXT NOT NULL`。

`detail` 在写入前截断至500字符。审计记录不能替代完整日志，且应避免向其中写入敏感原文。

### `quality_result`

`id INTEGER PK AUTOINCREMENT`、`batch_id TEXT NOT NULL`、`rule_code TEXT NOT NULL`、`rule_name TEXT NOT NULL`、`status TEXT NOT NULL`、`checked_rows INTEGER DEFAULT 0`、`failed_rows INTEGER DEFAULT 0`、`duration_ms REAL DEFAULT 0`、`details TEXT`、`created_at TEXT NOT NULL`。

状态为PASS/FAIL。导入时还写COMPLETENESS与UNIQUENESS；手动质量执行另有10项规则。

### `etl_job`

`id TEXT PK`、`name TEXT NOT NULL`、`source_table TEXT NOT NULL`、`schedule TEXT NOT NULL`、`enabled INTEGER DEFAULT 1`、`last_status TEXT`、`last_run TEXT`、`retry_limit INTEGER DEFAULT 3`。

初始化六个任务，schedule从 `0 2 * * *` 到 `25 2 * * *` 每5分钟错开。`etl.scheduler.scheduler` 简易轮询脚本可消费这些表达式并触发到期任务，但未接入容器常驻启动，也无并发锁与告警；`retry_limit` 尚未形成自动重试机制。

### `data_source`

`id TEXT PK`、`name TEXT NOT NULL`、`kind TEXT NOT NULL`、`config_json TEXT NOT NULL`、`enabled INTEGER DEFAULT 1`、`created_at TEXT NOT NULL`。

初始化六条CSV配置。接口虽允许登记 `mysql/oracle/sqlserver/api` 类型，但当前没有对应采集连接器；`config_json` 不应保存明文密码或Key。

## 9. 索引与约束清单

| 对象 | 约束/索引 |
|---|---|
| ODS | `ods_record(source_table, source_pk)`联合主键；`etl_batch.batch_id`主键 |
| 门诊 | `visit_id`主键；`idx_outpatient_date(visit_date, dept_code)` |
| 住院 | `visit_id`主键；`idx_inpatient_dates(discharge_date, admit_date, dept_code)` |
| 收费 | `charge_id`主键；`idx_charge_date(fee_date, dept_code, visit_type)` |
| 财务 | `record_id`主键；`UNIQUE(stat_date, dept_code)` |
| DWD宽表 | `(source_type, encounter_id)`主键；`idx_encounter_wide_date(start_date, dept_code)` |
| DWS科室日 | `(stat_date, dept_code)`主键；`idx_dws_date(stat_date, dept_code)` |
| DWS病种 | `(disease_code, dept_code)`主键；`dws_disease_day`另按日期/科室/病种联合主键 |
| DWS主题八表 | 七个日期主题按 `(stat_date, dept_code)` 主键并建日期索引；病种日表按 `(stat_date, dept_code, disease_code)` 主键 |
| ADS | `(metric_code, stat_date, grain, dept_code)`主键；`idx_ads_lookup(grain, stat_date, dept_code)` |
| 公共时间维 | `dim_date.date_key`主键 |
| 维度与定义 | 各自编码主键 |
| 审计 | 自增主键；`idx_audit_time(created_at)` |

当前没有为患者关联、DWD就诊关联或ADS批次建立额外表间外键。增加约束前必须评估历史数据、质量隔离和ETL顺序，不能仅在参考DDL中添加后就声称运行库已经具备。

1. 与业务方确认科室、床位、人力、费别和病种映射；未确认前持续显示教学标识。
2. 持续核对K02跨科去重、K14期间汇总与K27相对权重的边界测试；后续调整口径时同步代码、手册和回归测试。
3. 为K25闰日、空数仓、缺失科室日、跨科患者等边界补充测试。
4. 将财务CSV与收费明细做对账报表，不在未核对前混入K16—K25。
5. 评估ODS原文最小化、加密、留存和脱敏策略，避免把“DWD无直接身份字段”误写成全库脱敏。

### P2：按真实需求扩展能力

1. 若需K03—K05、K15、K30、K33—K36，先增加合法来源字段与质量规则，再实现公式，禁止补0或让LLM生成数值。
2. 若需正式DRG/DIP，接入授权分组器、官方权重与医保数据，另行验证；现有K26—K29只能保留为估算。
3. 若需自动采集，增加受控调度器、并发锁、重试与告警；当前cron元数据本身不会触发任务。
4. 若需数据库/API数据源，实现专用连接器、密钥管理和连通性测试，不把元数据登记当作已接入。
5. 若需外部共享，完成HTTPS、限流、默认口令治理、密钥轮换、令牌存储评估、备份恢复和安全测试。

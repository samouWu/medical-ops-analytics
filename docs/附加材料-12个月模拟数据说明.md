## 1. 为什么单独存放

用户要求将12个月数据作为附加内容，不修改当前主题展示。为避免破坏已经验收的主链路，本数据集采用完全隔离方案：

```text
原主库：data/derived/medical_ops.db                 2025-04-01 ~ 2025-06-30
附加库：data/supplemental_12m/derived/supplemental_12m.db  2025-04-01 ~ 2026-03-31
```

- 当前后端和前端未切换数据库，主题仍显示3个月数据。
- 附加数据不会自动进入主库、主线DWS/ADS或当前页面。
- 如确需使用12个月模式，可通过环境变量启动独立后端，但不属于默认演示流程。

## 2. 数据范围与来源

| 部分 | 日期范围 | 性质 |
|---|---|---|
| 原始给定数据 | 2025-04-01 至 2025-06-30 | 课程提供的真实给定模拟CSV，原样保留 |
| 模拟扩展 | 2025-07-01 至 2026-03-31 | 基于原始模板、科室分布和费用结构，用固定随机种子生成 |
| 合计 | 2025-04-01 至 2026-03-31 | 12个月附加模拟数据 |

扩展数据不是对真实医院趋势的推断。它只用于验证“时间跨度≥12个月时，ETL、DWS、ADS和指标服务是否仍能运行”。

## 4. 生成方法

1. 读取原始六份CSV，完整保留2025-04-01至2025-06-30记录。
2. 统计原始科室、就诊类型、住院日、病种、费用、LIS项目和结果分布。
3. 对2025-07-01至2026-03-31逐日生成：
   - 每科每日约9—10人次门诊；
   - 每科每日1—2人次住院；
   - 门诊收费按同科室、同就诊类型的原始收费模板生成；
   - 住院收费按同科室原始住院模板生成；
   - EMR每个住院一记录；
   - LIS每个住院1—3条结果；
   - 财务每科每日一条记录。
4. 生成患者ID、姓名、证件号和电话均为 `SIM-*` 前缀的合成标识，不创建真实个人身份。
5. 使用业务主键断言，确保六源主键无重复。
6. 在独立数据库中执行完整ETL，重建八主题DWS与ADS日/周/月结果。

> 前3个月仍保留课程原始数据中的身份字段；附加目录同样只能作为受控课程数据使用。

## 7. 复现方式

生成数据并自动构建独立数仓：

```bash
.venv/Scripts/python.exe scripts/build_supplemental_12m.py
```

只生成CSV、不执行ETL：

```bash
.venv/Scripts/python.exe scripts/build_supplemental_12m.py --skip-etl
```

临时以附加库启动后端（不作为默认演示）：

```bash
MEDICAL_DATA_DIR=data/supplemental_12m \
MEDICAL_DB_PATH=data/supplemental_12m/derived/supplemental_12m.db \
PYTHONPATH=backend \
.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8766
```

## 8. 使用边界

1. 该数据集是课程模拟扩展，不是医院真实数据，也不是真实趋势预测。
2. 生成数据只用于验证12个月时间范围下的ETL、分层汇总、ADS和指标计算。
3. 默认主题仍使用3个月主库，不自动切换。
4. 附加库不应被当作生产数据库，不应用于绩效、医保、DRG官方分组或临床决策。
5. 原3个月身份字段仍需受控管理；扩展患者身份是合成字符串。
6. 若后续需要将12个月接入主题展示，应独立做数据评审、指标复算、页面回归和性能评估，不能直接替换主库。

| 项目 | 内容 |

## 1. 文档目的

本文档定义平台的功能范围、数据范围、指标口径、非功能要求和验收标准，作为设计、开发、测试、验收和变更控制的统一需求基线。本文档描述“应做到什么”，不把当前实现状态写成需求本身；实现差异见第 12 节。

## 2. 项目背景与目标

医院运营数据分散在 HIS、EMR、LIS、收费和财务等系统，业务人员取数依赖人工导出与表格拼接，存在口径不统一、指标不可追溯、跨主题分析成本高的问题。平台目标是使用给定模拟数据建立一条可复现链路：

```text
多源文件接入 → ODS → DWD → DWS → ADS → API → 可视化/报表/智能问数
```

课程目标包括：掌握医疗数据治理、分层数仓、指标口径、后端服务、前端可视化、智能分析、测试与部署的完整工程过程。

## 3. 用户与角色

| 角色 | 需求与权限 |
|---|---|
| 系统管理员 admin | 用户与数据源管理、全量 ETL、质量执行、ADS 回刷、全量看板与审计 |
| 运营分析师 analyst | 全院指标分析、多维报表、导出、文件导入、单任务 ETL、质量执行 |
| 科室负责人 department | 仅查看授权科室指标；不可查询其他科室或全院明细组合 |
| 课程验收教师 | 检查需求、设计、数据、代码、测试、部署与成果物完整性 |

## 4. 数据范围与数据源

### 4.1 接入数据源

| 编号 | 数据源 | 文件/表 | 主键 | 关键字段 |
|---|---|---|---|---|
| DS-01 | HIS 门诊 | `his_outpatient.csv` | `visit_id` | 患者、科室、就诊日期、就诊类型、费用 |
| DS-02 | HIS 住院 | `his_inpatient.csv` | `visit_id` | 入院/出院、床位、住院日、费用、病种 |
| DS-03 | HIS 收费 | `his_charge.csv` | `charge_id` | 就诊类型、科室、费别、金额、收费日期 |
| DS-04 | EMR | `emr_record.csv` | `record_id` | 就诊、科室、诊断、病种 |
| DS-05 | LIS | `lis_report.csv` | `report_id` | 检验项目、结果、报告日期 |
| DS-06 | 财务 | `finance_excel.csv` | `record_id` | 日期、科室、收入、药品、耗材 |

要求至少接入 5 类数据源；本平台接入 6 类。文件源必须支持 CSV/XLSX/XLSM、字段识别、错误行反馈和幂等导入。数据库/API 数据源仅可登记，不在本课程初版接入范围。

### 4.2 数据量与时间范围

- 课程最终要求提供 12 个月模拟数据。
- 默认主主题使用课程给定数据，覆盖 2025-04-01 至 2025-06-30，共 91 天、59,922 行。
- 另提供独立的 12 个月附加数据集，覆盖 2025-04-01 至 2026-03-31，共 236,028 行，明确标记为“3个月原始数据 + 9个月模拟扩展”，不进入当前主题。
- 系统不得把 3 个月主题数据伪装成 12 个月；附加库与主库必须通过目录、数据库路径和页面范围明确区分。

### 5.4 智能分析约束

- 只允许 DeepSeek 或 Kimi，不接入 GPT。
- Key 只从服务端环境变量读取，禁止写入源码、前端或数据库明文字段。
- 外部模型只能接收问题与聚合指标上下文，不接收患者姓名、身份证、手机号等明细。
- 当前问数采用白名单指标语义解析与参数化查询，不执行大模型生成的任意 SQL。
- 若课程要求“自由 NL2SQL”，需另行实现 SQL 生成、AST 白名单校验、只读事务和审计，不得直接把模型输出交给数据库。

## 8. API 与响应规范

- 业务接口统一前缀 `/api/v1`，除登录外均需 `Authorization: Bearer <JWT>`。
- 正常响应：`{"code":0,"message":"success","data":...,"trace_id":"..."}`。
- 错误响应：HTTP 状态码与业务 `code` 一致，`message` 可读，`data` 为空，附 `trace_id`。
- 主要状态码：400 参数/业务错误、401 未认证、403 越权、404 不存在、409 冲突、413 文件超限、422 校验/不可算、500 内部错误。
- OpenAPI 文档由 FastAPI 自动生成于 `/docs` 和 `/openapi.json`。

## 9. 数据安全与合规要求

1. DWD 不出现 `patient_name`、`id_card`、`phone` 明文，只使用加盐散列 `patient_key`。
2. ODS `payload_json` 当前保留源行原文，必须与数据库、备份、导入文件按敏感数据管理。
3. 不得用真实患者数据替换模拟数据后直接对外部署。
4. 科室用户的所有查询、导出和 AI 请求必须在服务端二次鉴权。
5. 登录、导入、ETL、质量、查询、导出和 AI 操作应写入审计，禁止把敏感原文写入审计详情。
6. 外部 LLM 出向属于网络数据传输，部署方需自行完成合规评估。

## 10. 验收标准

### 10.1 必须满足

- 六源接入成功，错误为 0 或可解释；核心指标与源文件可复算。
- 四层数仓、8 张主题 DWS、公共时间维和 DDL 一致。
- 不少于 30 项正式可计算指标；9 项不可算指标明确拒绝。
- 日/周/月指标与区间回刷可用；重复回刷结果一致。
- JWT/RBAC/科室隔离、审计、统一响应和 OpenAPI 可用。
- 后端测试全部通过且覆盖率 ≥85%；前端测试、Lint、构建通过。
- 50 问评测准确率 ≥85%，且评测材料可复现。
- 前端看板、主题、下钻、多维、导出、问数、报告和质量页面可演示。
- Docker、深度性能与安全、正式试运行和验收材料按课程要求完成。

## 12. 变更控制

- 需求变更必须同步更新本文件、设计、指标口径、测试用例和成果物清单。
- 指标公式变更必须同时更新代码、口径手册、自动测试和历史数据回刷。
- 数据源模板变更必须先更新需求、数据字典、ODS 字段和质量规则，不得直接修改解析代码绕过校验。

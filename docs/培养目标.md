# 项目培养目标与能力达成说明

| 项目 | 内容 |
|---|---|
| 项目名称 | 医疗运营数据主题分析平台 |
| 文档版本 | V1.0 |
| 日期 | 2026-11-20 |
| 适用对象 | 课程学生、指导教师、验收教师 |

## 1. 培养定位

本项目定位为“医疗业务理解 + 数据工程 + 软件工程 + 智能分析”的综合实践。学生不是只完成页面或单一算法，而是要把模拟医疗数据加工成可解释、可追溯、可演示的运营分析系统，并形成需求、设计、开发、测试、部署和验收的完整证据链。

## 2. 总体培养目标

完成项目后，应具备以下能力：

1. 能从医疗业务场景提炼数据需求和指标口径，而不是直接堆砌图表。
2. 能设计并实现 ODS/DWD/DWS/ADS 分层数仓和主题集市。
3. 能开发可用的后端 API、前端看板和数据导出功能。
4. 能处理权限、隐私、审计、质量与口径边界。
5. 能设计测试、量化覆盖率、发现并修复数据与代码缺陷。
6. 能在明确安全边界下接入大模型能力，不把模型输出当作事实。
7. 能编写部署、操作、评审、验收和总结材料，完成可交付闭环。

## 3. 分项能力目标与证据

### 3.1 业务分析与需求工程

目标：

- 理解门诊、住院、收费、药品、耗材、病种、资源和患者服务主题。
- 把业务问题转化为可计算指标、维度和筛选条件。
- 识别缺失字段，明确“不可计算”，不伪造结果。

达成证据：

- `docs/需求规格说明书.md`
- `docs/指标口径手册.md`
- 39项指标目录，30项可算、9项不可算
- `docs/成果物清单.md`

评价标准：

| 等级 | 表现 |
|---|---|
| 优秀 | 能解释指标业务含义、口径、分母和边界，能指出不可算原因 |
| 合格 | 能列出主要指标并完成基本计算 |
| 不合格 | 只展示数字，无口径和来源说明 |

### 3.2 医疗数据治理与数仓建模

目标：

- 识别六类数据源的主键、日期、字典和敏感字段。
- 建立分层模型、批次、质量规则、公共维表和主题集市。
- 处理去重、缺失、格式、映射和隐私散列。

达成证据：

- `backend/etl/jobs/pipeline.py`
- 八张主题 DWS、`dim_date`、DWD统一宽表、25 张参考 DDL 表
- 10 项质量规则和 `data/init/quality_rules.csv`
- 自动化聚合一致性和主键测试

评价标准：

- 能说明 ODS 与 DWD 的职责差异。
- 能证明重复导入幂等。
- 能识别 ODS 原文保留与 DWD 脱敏的边界。

### 3.3 指标与 ADS 计算

目标：

- 统一指标编码、单位、主题和公式。
- 处理零分母、去重人数、跨科室汇总和期间边界。
- 实现日/周/月粒度和区间回刷。

达成证据：

- `backend/app/services/metrics.py`
- `backend/app/services/analytics.py`
- `backend/etl/jobs/pipeline.py` 的 ADS 构建
- `backend/etl/jobs/ads_refresh.py`
- `docs/指标口径手册.md`

评价标准：

- 能解释“门诊人次”和“门诊人数”的区别。
- 能复算至少 K01、K08、K12、K13、K16、K19、K22。
- 能说明 DRG/CMI 为教学估算，不是官方分组。

### 3.4 后端服务与安全

目标：

- 使用 FastAPI 构建统一响应、异常处理、OpenAPI、JWT、RBAC 和审计。
- 实现科室级数据隔离和敏感字段保护。
- 编写接口测试并达到覆盖率要求。

达成证据：

- `backend/app/` 服务源码
- 36 项后端测试、86.83% 覆盖率、19项前端测试和15项E2E
- `docs/测试计划与报告.md`
- `docs/数据字典.md`

评价标准：

- 未登录返回401，越权返回403。
- 科室用户不能通过手工参数访问其他科室。
- 错误响应含 trace_id，不泄露堆栈。

### 3.5 前端可视化与交互

目标：

- 使用 Vue3 + ECharts 完成驾驶舱、主题、指标、多维、问数、报告和治理页面。
- 处理加载、空、错误、重试、导出和权限。
- 实现筛选、下钻、周/月粒度和同环比展示。

达成证据：

- `frontend/src/`
- 16 项前端单元测试、ESLint、生产构建
- `docs/用户操作手册.md`

评价标准：

- 页面能真实请求后端，不使用硬编码业务数字。
- 图表可交互，筛选条件能传递。
- 401 会清理会话并返回登录页。

### 3.6 智能分析与模型边界

目标：

- 使用 DeepSeek/Kimi 而非 GPT。
- 仅发送问题和聚合上下文，不发送患者明细。
- 模型失败时有明确的本地回退标识。
- 能评测问数准确率，而非只演示一个问题。

达成证据：

- `backend/app/llm/semantic.py`
- `backend/etl/evaluation/questions.json`
- 50问、100% 受控问数评测报告
- `docs/50问评测报告.md`

评价标准：

- 能说明受控语义问数与自由 NL2SQL 的区别。
- 不将模型生成的数字当作指标事实。
- 能展示危险请求拦截。

### 3.7 测试、评审与质量保障

目标：

- 设计覆盖功能、权限、数据、边界和导出的测试。
- 能定位和修复真实缺陷。
- 能形成测试用例、缺陷清单、评审记录和验收结论。

达成证据：

- `backend/tests/`
- `frontend/tests/`
- `docs/测试用例与缺陷清单.md`
- `docs/代码评审记录.md`

评价标准：

- 不以“页面能打开”代替测试。
- 不隐瞒失败项和未验证项。
- 缺陷有等级、修复、回归和关闭记录。

### 3.8 部署、运维与交付

目标：

- 能编写本地启动和 Docker Compose 部署材料。
- 能说明环境变量、数据库卷、健康检查和回滚。
- 能完成文档、数据和过程归档。

达成证据：

- `deploy/`、`scripts/`、`.env.example`
- `docs/部署运维手册.md`
- `docs/成果物清单.md`
- `docs/验收报告.md`

评价标准：

- 部署命令可复现。
- 密钥不写入代码。
- 容器未实测时不冒充部署通过。

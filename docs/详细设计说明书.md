### 2.2 索引

- `dwd_outpatient_visit(visit_date, dept_code)`
- `dwd_inpatient_stay(discharge_date, admit_date, dept_code)`
- `dwd_charge_detail(fee_date, dept_code, visit_type)`
- `dws_dept_day(stat_date, dept_code)` 及八张主题表日期/科室索引
- `ads_metric_result(grain, stat_date, dept_code)`
- `audit_log(created_at)`

### 2.3 事务与幂等

- 每次请求通过 `db_session()` 获取连接，成功 `commit`，异常 `rollback`。
- 批次创建与更新使用独立事务。
- ODS/DWD 使用 `INSERT OR REPLACE`，以业务主键幂等。
- DWS/ADS 全量或区间删除后重算，保证重复执行结果一致。
- 源文件内同主键重复：内容相同忽略，内容不同记错误。
- 源文件删除的历史记录不会被自动删除，这是全量文件同步的已知限制。

## 3. ETL 详细设计

### 3.1 模板识别

`SOURCES` 定义每类源的路径、主键、日期字段、必填字段。`detect_source` 在多个模板字段集合匹配时选择必填字段最多者，降低宽表误判。

### 3.2 行级处理

1. 主键非空。
2. 日期 `date.fromisoformat`。
3. 数值转 float，拒绝 NaN/Inf/负数。
4. 患者ID经 `SHA-256(salt:patient_id)` 截取24位生成 `patient_key`。
5. 行内容规范化为 JSON 用于冲突判断。
6. 写 ODS 原文与 DWD 标准列。

增量模式先读取目标DWD的最大日期作为水位，只接收日期大于水位的源记录；跳过量计入 `skipped_rows`，不当作错误。`import_with_retry` 按任务的 `retry_limit` 重试失败源，每批次仍保留独立失败记录。该方案不是CDC：源文件内历史记录更新不会自动捕获，删除也不会同步。

### 3.3 质量规则

10项规则覆盖门诊/住院/收费主键、日期逻辑、金额非负、科室/病种映射、LIS值域、财务非负。规则集快照见 `data/init/quality_rules.csv`。质量分数 = `100 - 失败行/检查行×100`，无检查行按100。

### 3.4 DWS 构建

1. 遍历门诊按 `(visit_date,dept_code)` 汇总人次、人数。
2. 遍历收费按日期/科室/就诊类型/费别累计收入。
3. 遍历住院，按入院日记入院、出院日记出院，逐日展开占用床日。
4. LIS 通过 `visit_id` 关联门诊或住院科室，未关联记录不进入科室指标。
5. 写入 `dws_dept_day`，然后派生八张主题DWS。
6. `dws_disease_day` 按出院日/科室/病种聚合。

### 3.5 ADS 设计

时间桶：

- day：`YYYY-MM-DD`
- week：周一日期
- month：月首日期

指标集合30项：全部可算指标均预计算；其中22项基础/比率指标由DWS直算，K09、K25—K29、K31、K32复用统一指标服务后写入。计算步骤：

1. 按日期读取 DWS。
2. 将日记录累加到目标时间桶和科室。
3. 对院级 `ALL` 汇总可加指标。
4. 门诊/住院患者数用 DWD 按时间桶直接 `COUNT(DISTINCT patient_key)`，不累加各日人数。
5. 计算比率，零分母为 `NULL`。
6. 床位周转：`出院人次×桶内实际天数/开放床日`。
7. 写入 ADS，按 `(metric, bucket, grain, dept)` 替换。

区间回刷：

```text
输入 start/end/grain/dept
→ 扩展为完整日/周/月桶
→ DELETE 指定粒度同桶数据
→ 从DWS/DWD重算
→ INSERT OR REPLACE
```

## 4. 指标服务详细设计

### 4.1 指标目录

`METRICS` 元组字段：编码、名称、主题、单位、可算标记、口径说明。目录初始化到 `metric_definition`，API 实时读取代码目录。`GET /metrics` 默认只返回30项可算指标，避免页面展示无法计算的项；管理员传 `include_unsupported=true` 可审计完整39项定义。

### 4.2 科室范围

```python
def scope(user, dept_code, column="dept_code"):
    allowed = user.get("dept_codes") or []
    if dept_code and dept_code not in allowed and allowed:
        raise PermissionError
```

- 有科室参数：校验后返回等值条件。
- 科室用户未给参数：自动限制到授权科室。
- 全院用户：`1=1`。

所有主题查询、趋势、明细、导出与 AI 均必须调用该函数。

### 4.3 指标公式实现

- 简单可加指标：DWS 聚合。
- 去重人数：DWD `COUNT(DISTINCT patient_key)`。
- 比率：`safe_ratio` 统一零分母处理。
- DRG/CMI：按病种费用/住院日相对全院基准计算，属于教学估算。
- 收入同比：缺上年数据时返回空，不伪造增长。
- 月/周趋势：将日期分组后逐桶调用汇总公式，确保比率先汇总分子分母再相除。

## 5. 权限与安全详细设计

### 5.1 JWT

- 算法 HS256，包含 `sub`、`role`、`exp`。
- 默认有效期 480 分钟，可由环境变量配置。
- 每次请求解析并校验签名、过期时间、用户启用状态。

### 5.2 RBAC

| 操作 | admin | analyst | department |
|---|---|---|---|
| 查看授权看板 | 是 | 是 | 是 |
| 导入文件 | 是 | 是 | 否 |
| 单任务ETL/质量 | 是 | 是 | 否 |
| 全量ETL/ADS回刷 | 是 | 是（ADS） | 否 |
| 用户/审计 | 是 | 否 | 否 |
| 科室越权 | 拒绝 | 拒绝 | 拒绝 |

### 5.3 敏感信息

- DWD 无直接身份字段；ODS 原文留存是已知风险。
- 危险问数正则拦截 SQL 修改词、身份证、手机号、患者姓名等。
- 报告和 LLM 只使用聚合指标，不发送患者明细。
- 审计详情不得写入敏感原文。

## 6. 智能问数详细设计

1. 长度1—300字。
2. 危险正则匹配即403。
3. 指标别名按最长优先匹配，覆盖39项目录中的可算名称与常用简称。
4. 科室全名及去“内科/外科”简称匹配；科室用户自动绑定授权科室。
5. 时间支持指定年月、仅月份、本月、上月、本周、上周、近N天；无时间时用页面筛选或全期。
6. 调用统一指标服务计算，生成趋势点。
7. 有Key时调用DeepSeek/Kimi生成80字内解读；失败标记 `local-rules-fallback`。
8. 返回 `query_mode=controlled-metric-query`，明确不是自由SQL执行。

50问题库评测四项同时正确才通过：指标、科室、统计期起点、结果非空。

## 7. 报表与导出

### 7.1 多维报表

- 请求：指标（最多8）、维度（date/dept_code）、过滤、粒度、对比方式。
- 行生成：
  - 日期×科室：逐科室取时间序列。
  - 仅科室：每科一行汇总。
  - 仅日期：时间序列。
- 同比：月份减1年、日减365天、周减364天；环比：上一月/日/周。
- 前值为空或0时对比值为空。
- Excel使用openpyxl，首行冻结。

### 7.2 主题导出与PDF

- 主题Excel：指标卡 + 维度明细。
- PDF：reportlab + `STSong-Light` CID字体。
- 文件名通过 `Content-Disposition` 返回，前端解析并下载。

## 8. 前端设计

### 8.1 状态与请求

- `appState` 保存元数据与日期范围；`filters` 保存日期/科室。
- `client.js` 注入 Bearer Token，统一处理401、业务错误和Blob。
- 请求竞态使用递增 `requestId`，避免旧请求覆盖新结果。

### 8.2 图表

- `EChart.vue` 管理 init/setOption/resize/dispose/click。
- `ResizeObserver` 响应容器尺寸变化。
- 折线/柱/饼配置工厂统一颜色、坐标轴、Tooltip和XSS转义。
- 点击事件向父页面发送分类名称，用于科室下钻。

### 8.3 页面交互

- 全局筛选条同步到所有页面；下钻通过修改 `filters.dept_code` 并重新取数。
- 加载、错误、空态由 `StateBlock` 统一展示。
- 表格分页由 `DataTable` 处理，支持百分比格式化。

## 9. 错误处理

| 场景 | HTTP | 行为 |
|---|---:|---|
| 参数校验失败 | 422 | 统一错误 envelope，含字段错误 |
| 未登录/令牌失效 | 401 | 前端清理会话并跳转登录 |
| 科室越权 | 403 | 不返回数据 |
| 指标不可算 | 422 | 明确说明缺源字段 |
| 文件类型/大小错误 | 400/413 | 不落库，临时文件清理 |
| 主键冲突 | 400/批次PARTIAL | 错误行指出行号和原因 |
| LLM失败 | 200 | 返回本地回退标识，不伪装成功 |
| 内部异常 | 500 | 仅返回trace_id，敏感堆栈不暴露 |

## 11. 部署与配置

- `MEDICAL_DB_PATH` 控制数据库位置。
- `MEDICAL_SECRET_KEY`、`MEDICAL_HASH_SALT` 必须替换默认值。
- LLM变量：`LLM_PROVIDER` + 对应供应商 Key/URL/Model。
- Docker启动自动全量ETL；生产化应拆分迁移、ETL和API启动。
- 备份前建议停止写入或使用SQLite在线备份API，不能只复制WAL状态不一致的文件。

## 12. 已知技术债

1. 安全NL2SQL接口已实现SQL白名单、写操作拒绝和只读事务，但真实DeepSeek/Kimi SQL生成未配置Key验证，不能把受控模板解析与自由NL2SQL等同。
2. ADS已预存全部30项可算指标，共35,640行。
3. DWS/ADS全量重建耗时随数据量线性增长。
4. 已实现按DWD日期水位过滤和失败重试，仍无任务DAG、并发锁、告警和分布式调度。
5. 已新增统一 `dwd_encounter_wide`，但多数指标仍直接读取按源标准表。
6. 已补用户/角色/数据源/任务管理页与CRUD API；自定义角色和细粒度权限矩阵仍为固定角色模型。
7. 已完成8并发120请求单机冒烟，P95约2.32秒；不构成生产容量或高并发SLA结论。
8. 仅在SQLite验证，DDL未在PostgreSQL执行。

# 项目说明

## 1. 项目定位

医疗运营数据主题分析平台是面向课程教学的端到端样例，展示模拟业务文件如何经过数据接入、分层数仓、统一指标、可视化、自然语言查询和质量治理形成分析应用。

本项目不是医院业务系统，不连接真实HIS/EMR/LIS，不提供诊疗建议，也未完成生产验收。页面和报告中的结果只适用于随项目提供的模拟数据及明确的教学口径。

## 2. 已实现范围

- 六份模拟CSV接入：门诊、住院、收费、EMR、LIS、财务。
- ODS原始记录留存、DWD标准化明细及统一 `dwd_encounter_wide` 宽表、八张DWS主题日集市、公共 `dim_date` 时间维和ADS三粒度指标。
- 管理驾驶舱及门诊、住院、收入、药品、耗材、病种、资源、服务八类主题；支持点击科室图表下钻并返回全院。资源效率页使用“床位使用率＋床位周转次数”双柱状图和科室资源明细。
- 40项指标定义中30项可计算；指标查询页面默认只展示这30项，日/周/月趋势、同比/环比、多维组合查询与多维Excel导出可用。
- 全部31项可算指标在ADS预计算日/周/月结果，支持按日期区间幂等回刷。
- 结构化固定四章节周报/月报、异常归因及PDF导出。
- 受控语义问数、指标知识问答、安全只读NL2SQL接口、日期/科室/指标解析，以及DeepSeek/Kimi聚合结果解读；50问评测50/50通过。
- 登录认证、三类角色、科室数据范围、数据质量、增量ETL、失败重试、全量GET审计、用户/角色/数据源/任务管理。
- SQLite参考DDL、前后端Docker镜像、Nginx与Compose演示部署材料。
- 附加12个月模拟数据集与独立数仓（236,028行），按用户要求不进入默认主题。

未实现的能力不得从界面或元数据推断为已具备：`etl.scheduler.scheduler` 已具备到期触发、增量抽取和失败重试参数，但未接入容器常驻启动，也没有任务DAG依赖、并发锁和告警，不能等同于生产调度平台；数据库/API数据源仅保存配置并返回“需专用连接器”，没有MySQL/Oracle/SQL Server/API采集实现；九项缺字段指标没有结果。安全NL2SQL接口只接受模型生成后的单条聚合SELECT，并做表/列白名单、写操作拒绝和只读事务校验；真实模型生成效果仍需有效Key验证。

## 3. 架构与数据流

```text
六份模拟CSV / 管理端上传文件
             │
             ▼
      etl.jobs.pipeline
  模板识别、日期数值校验、主键去重
             │
       ┌─────┴─────┐
       ▼           ▼
   ods_record   DWD六张明细表
  原始JSON留痕  patient_key散列化
                   │
                   ▼
公共dws_dept_day + 八张主题DWS
门诊/住院/收入/药品/耗材/
病种/资源/患者服务
                   │
          ┌────────┴────────┐
          ▼                 ▼
   ads_metric_result    服务层按需计算
  日/周/月核心指标      其余指标动态计算
          └────────┬────────┘
                   ▼
          FastAPI /api/v1 接口
                   │
          ┌────────┴────────┐
          ▼                 ▼
   Vue 3 + ECharts       XLSX/PDF导出
```

- 后端入口：`backend/app/main.py`，启动时调用 `init_db()` 建表并初始化演示字典、用户和任务。
- 数据库连接：`backend/app/core/database.py`，每次连接启用外键与WAL，默认路径由 `MEDICAL_DB_PATH` 覆盖。
- 转换权威实现：`backend/etl/jobs/pipeline.py`。`sql/` 是与其对应的SQLite参考DDL，不是独立的自动迁移或另一套ETL。
- 指标权威实现：`backend/app/services/metrics.py` 与 `backend/app/services/analytics.py`。
- 前端通过同源 `/api/v1` 访问后端，Vite开发代理目标为 `127.0.0.1:8765`。

## 4. ETL行为

1. 每次导入创建 `etl_batch`，记录源文件SHA-256、状态、行数、错误数和时间。
2. 按模板必填字段识别或校验数据；支持UTF-8/UTF-8-BOM CSV，以及XLSX/XLSM。
3. 校验业务主键、ISO日期、数值、负数；单条错误进入错误清单，其余合格记录继续导入，批次标记为 `PARTIAL`。
4. 同一文件内完全相同主键与内容的重复行幂等去重；同主键不同内容报冲突。
5. `ods_record` 按 `(source_table, source_pk)` 替换，DWD按各自主键替换；因此重复执行不会增加同主键行数。
6. 全量命令依次重读六个源文件，随后删除并重算DWS、ADS。它不会清除源文件中已不存在的历史DWD主键。
7. LIS科室汇总优先关联门诊、再关联住院就诊记录；无法关联就诊科室的记录不进入科室日汇总。

上传接口只允许管理员和分析师，单文件上限20 MiB；Nginx演示配置留出25 MiB请求空间，应用仍执行20 MiB文件限制。

## 5. 角色与权限

| 能力 | admin | analyst | dept_hn |
|---|---:|---:|---:|
| 登录、看板、主题、指标、报告、AI查询 | 是 | 是 | 是，仅HN |
| 查看质量、ETL任务、数据源 | 是 | 是 | 是，不代表可调全院明细 |
| 执行质量规则、上传文件、运行单个ETL任务 | 是 | 是 | 否 |
| 全量ETL、新建数据源、查看审计日志 | 是 | 否 | 否 |
| 跨科室查询 | 是 | 是 | 否，越权返回403 |

科室范围由后端根据 `app_user.dept_codes_json` 强制过滤，前端隐藏入口不能替代后端授权。`enabled=0` 或无效令牌返回401。

## 6. API概览

所有下列路径除 `/health` 外均带 `/api/v1` 前缀。除登录外均需Bearer令牌。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 无认证健康检查，实际完整路径就是 `/health` |
| POST | `/auth/login` | 用户登录并获取JWT |
| GET | `/meta` | 科室、可用日期范围、启用数据源数量 |
| GET | `/dashboards/management` | 管理驾驶舱 |
| GET | `/dashboards/department`、`/dashboards/topic` | 分别映射资源、收入主题的兼容入口 |
| GET | `/analytics/{topic}` | 八类主题分析 |
| GET | `/metrics` | 默认返回30项当前可查指标（K25缺上年同期已隐藏），含 `formula` 计算公式；`include_unavailable=true`返回30项，`include_unsupported=true`返回完整40项目录 |
| GET | `/metrics/{code}/values` | 指标汇总与趋势，`grain=day/month` |
| POST | `/reports/query` | 1—8个可算指标的多维报表 |
| GET | `/export/{topic}` | 主题Excel导出 |
| POST | `/ai/ask` | 自然语言聚合指标查询 |
| POST | `/reports/generate` | 生成周报或月报 |
| POST | `/reports/export/pdf` | 生成并导出PDF报告 |
| GET | `/quality/latest` | 最新质量结果；无历史时会触发一次检查 |
| POST | `/quality/run` | 执行10项质量规则 |
| POST | `/imports/auto` | 自动识别模板并导入文件 |
| GET | `/etl/jobs` | ETL任务元数据 |
| POST | `/etl/jobs/{job_id}/run` | 运行指定文件任务 |
| POST | `/etl/run-all` | 重读六份文件并重建汇总 |
| GET/POST | `/data-sources` | 查询或登记数据源配置 |
| POST | `/data-sources/{source_id}/test` | 文件源连通测试；其他类型明确返回未实现 |
| GET | `/audit/logs?limit=100` | 管理员查看审计，limit范围1—500 |

常用查询参数为 `start=YYYY-MM-DD`、`end=YYYY-MM-DD`、`dept_code=HN`。不传日期时使用数仓最小/最大日期。主题取值为 `outpatient`、`inpatient`、`revenue`、`drugs`、`consumables`、`disease`、`resources`、`service`。

报告请求示例：

```json
{
  "period": "month",
  "date": "2025-06",
  "dept_code": "HN"
}
```

`period` 仅支持 `week` 或 `month`。不传 `date` 时以数仓最大日期为锚点。智能问数以 `question` 为实际解析入口，支持有限的指标别名、月份、上月、近7天、本周和科室名称，不是任意SQL或任意语义查询。

## 7. 智能分析与数据出向

- `LLM_PROVIDER=deepseek` 为默认，`kimi` 可切换；Key为空时使用本地规则。
- 本地规则负责指标、时间和科室解析，并从SQLite取得聚合值，不依赖外部模型生成数字。
- 配置Key后，外部模型只承担短文本解读。智能问数发送原始问题与聚合指标事实；报告发送聚合段落。
- 供应商HTTP错误或响应解析失败时回退本地模板，provider显示 `local-rules-fallback`。
- 危险SQL关键词和部分患者隐私词会被拒绝，但正则拦截不是完整的隐私或安全识别方案。

## 8. 教学边界与已知限制

- 九项缺字段指标不可算；不能通过补0、硬编码或模型生成方式“补齐”。
- 科室床位和人力由初始化列表提供，`mapping_status` 默认“待业务确认”。
- K26—K29为教学估算，不能替代正式DRG/DIP分组、权重和医保结算数据。
- 核心收入采用账单口径（门诊收费单金额+住院结算总费用，课程数据集为2,774.58万元）；药品、耗材结构按收费明细口径；财务CSV当前不参与核心收入对账。
- ODS保存原始JSON，直接身份字段并未在ODS层脱敏；DWD才不保存姓名、证件号、手机号等直接标识。
- 报告中的35%药占比是固定教学警戒线，不是政策阈值或医疗建议。
- 默认口令、HTTP、本地令牌存储、缺少登录限流和密钥轮换意味着只能用于受控本地演示。
- 未进行高并发、容量、容灾或生产安全测试，不作百万并发等性能声明。

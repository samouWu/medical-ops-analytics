## 2. 建议PPT结构

### 第1页：封面

- 标题：医疗运营数据主题分析平台
- 副标题：从多源模拟数据到运营指标与智能问数
- 姓名、学号、指导教师、日期

### 第2页：业务背景与目标

- 医疗数据分散在 HIS、EMR、LIS、收费、财务。
- 痛点是口径不统一、取数慢、跨主题分析难。
- 目标：建立可追溯的分层数仓与八主题运营分析平台。
- 边界：教学模拟数据，不是生产系统。

### 第3页：总体架构

放入概要设计的架构图，强调：

- Vue3 → FastAPI → SQLite数仓。
- ODS/DWD/DWS/ADS 四层。
- DeepSeek/Kimi只做聚合解读，不接GPT。

### 第4页：数据链路与质量

- 六源59,922行、0错误。
- 批次、SHA-256、错误行、幂等。
- 10项质量规则。
- DWD去除直接身份，使用patient_key。
- ODS原文保留的风险说明。

### 第5页：八主题DWS与ADS

- 8张主题表、7,679行。
- 公共dws_dept_day、dim_date。
- ADS 30项可算指标日/周/月35,640行。
- 区间回刷幂等。
- 关键对账：月度K16合计44,260,283.80元。

### 第6页：指标体系

- 39项目录，30可算，9不可算。
- 展示门诊、住院、收入、DRG、资源、服务六类代表指标。
- 强调K01与K02、K13与K14的区别。
- DRG/CMI为教学估算。

### 第7页：系统演示

- 驾驶舱：指标卡、趋势、科室排行。
- 任选一个科室柱形下钻并返回全院。
- 打开住院或收入主题。
- 指标查询切换日/周/月。

### 第8页：多维报表与智能问数

- 选择K01、K16，日期×科室，月粒度，同比/环比。
- 导出Excel。
- 提问：“2025年5月呼吸科门诊量是多少？”
- 强调受控问数，不是自由SQL。

### 第9页：安全与权限

- JWT + PBKDF2 + 三角色。
- 科室用户在服务端强制数据范围。
- 未登录401、越权403、危险问数403。
- 审计与Trace ID。
- 已知边界：默认口令、无限流、无HTTPS。

### 第10页：测试与质量

- 后端30/30，覆盖率81.62%。
- 前端18/18、Lint 0错误、730模块构建、Edge E2E 9/9。
- 50问50/50、100%。
- 八主题聚合一致性、ADS回刷幂等。
- Docker、E2E、压测、安全专项未完成。

### 第11页：难点与解决

- 指标去重与跨科汇总。
- 周/月ADS时间桶覆盖缺陷及修复。
- 科室权限贯穿LIS/主题/AI/导出。
- LLM不可用时明确回退。
- 50问题库的四维判定。

### 第12页：不足与改进

- 默认主题3个月 vs 独立附加12个月（已生成但不进入主题）。
- 30项ADS已落表；模型真实生成SQL仍需Key验证。
- Canvas人工点击、Docker、生产容量与深度安全未验证。
- 正式试运行、培训和签字尚未完成。

### 第13页：总结

- 已形成可运行、可测试、可追溯的课程初版。
- 数据、指标、权限和测试有真实证据。
- 不把未验证项包装成已完成。

## 4. 重点问答

### Q1：为什么只有27/30项可算？

当前39项目录中30项可算。不可算9项是K03、K04、K05、K15、K30、K33、K34、K35、K36，分别缺预约、退号、手术、设备、成本、候诊、满意度、报告时限字段。没有用0或模型补造。

### Q2：门诊人次和门诊人数有什么区别？

人次是就诊记录数，同一患者多次就诊计多次；人数是统计期患者去重数。K01与K02不能混用，跨日人数也不能简单相加。

### Q3：床位周转为什么不是出院/开放床日？

周转次数应为出院人次/同期平均开放床位数。用开放床日作分母会因期间天数放大/缩小，K14已按“出院×期间天数/开放床日”处理。

### Q4：周/月指标如何保证正确？

按完整时间桶聚合DWS，去重人数直接查DWD；K16月合计已与DWS总额核对一致；区间回刷先删同桶再重算，重复执行幂等。

### Q5：LLM会不会乱算？

LLM只对已计算好的聚合事实做文字解读，不生成或执行SQL，不接触患者明细。无Key时明确返回local-rules，失败标记fallback。

### Q6：50问100%是否说明能回答所有问题？

不能。它是固定课程题库的受控语义评测，不代表开放域自由问数。自由NL2SQL是未完成项。

### Q7：数据安全如何保证？

DWD去直接身份、JWT/RBAC、科室服务端隔离、审计、危险问数拦截、LLM只发聚合。ODS仍保留原文，是已知风险。

### Q8：为什么默认主题只有3个月？

课程提供的数据只有2025年4—6月，默认主题必须保持原始数据。为额外验证时间跨度，已生成独立的12个月扩展库：前3个月原样保留，后9个月按原始模板确定性地模拟，236,028行，独立完成ETL/DWS/ADS并对账；按用户要求不进入主题页面。它不是真实趋势数据。

### Q9：为什么没有Docker实测？

当前环境没有Docker。配置已写，但不能把配置当作实测通过。

### Q10：项目最大不足是什么？

仍未闭环：默认主题接入12个月、真实Key模型生成SQL、Docker实测、生产容量与深度渗透、正式试运行培训和签字。受控问数、知识问答、安全SQL白名单、CRUD、axios、5图表、E2E和基础对账已完成。
